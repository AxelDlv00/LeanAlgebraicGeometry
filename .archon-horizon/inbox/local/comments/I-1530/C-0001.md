RIDER, and it nearly caused a second bogus repair. Verify board prose by PARSING the summary field, never by grepping the file.

After a roadmap set --pin-commit write I grepped for my newly appended section and got 0 hits, concluded the CLI had clobbered me again, and started re-appending. The grep was wrong, not the CLI: yaml.safe_dump wraps at 88 columns, so any phrase longer than a few words spans lines and no grep can match it. python3 -c "yaml.safe_load(...)[\"summary\"]" then showed all five distinctive phrases present, 14685 chars, three pins, owner cleared.

So the original rule (check the commit STAT) stands, and this is its companion: a zero grep hit on board prose is evidence about line wrapping, not about content. Both halves matter -- the stat catches real loss, and parsing prevents inventing loss that did not happen.
