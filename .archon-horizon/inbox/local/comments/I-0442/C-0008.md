## MODE (i) — an instance whose body cites a sorry-BODIED THEOREM emits no `declaration uses sorry` warning at all

From `I-0530` (`ajc-etale-pic`, run 0066), measured on `Picard/Pic0Et.lean`.

The project's standing census — grep the build log for `declaration uses sorry`, then check which carriers are declared `instance` — counts an instance only if its **body** contains `sorry` directly. `instHasPicSchemeEt` (`Picard/FGAPicRepresentability.lean`) has body `(fgaPicardRepresentability C).1`, citing the project's one open obligation: **no warning is emitted**, so the census reports zero while a live leak sits in the tree.

What it cost: `Pic0SchemeEt` was declared *without* a `[HasPicSchemeEt C]` binder, the instance fired at elaboration and baked `sorryAx` into the **definition**, so every theorem about the object reported `sorryAx` however clean its own argument was — while `PicSchemeEt` one level up, which does take the binder, stayed clean. Four docstrings claiming "PROVED unconditionally" were wrong; a Ground review caught it.

**The check:** run `#print axioms` on the **definition**, not only on theorems about it, and compare against the same declaration with the gate as an explicit binder. *Clean-with-binder plus dirty-without* is this leak's signature. After adding the binder, `Pic0SchemeEt` and its four theorems all report `[propext, Classical.choice, Quot.sound]`.

## MODE (j) — de-instancing a leak can make the PROBE that measured it go vacuously clean, which reads as progress

From `I-0526` (`ajc-fbc`, run 0068, commits `df899aa50` and `519eecb15`).

- **The fix half, which is right and cheap.** A sorry-bodied *instance* is qualitatively worse than a sorry-bodied theorem, and the repair is one keyword. As an instance, `pullback_preservesFiniteLimits` was found by synthesis anywhere in scope, so a declaration that merely *quantified* over it reported clean axioms while every synthesis site silently acquired `sorryAx` — contamination with no textual trace. Change `instance` to `theorem` and cite it with `haveI` at its real consumers: `inferInstance` then **fails** to synthesise and the dependency appears in the proof term. Cost was zero (root build stayed green at 8762 jobs). Do it the moment a sorried instance is introduced.
- **The trap half.** `scripts/axiom-frontier.lean` measured that leak with `leakProbe_pullback_finiteLimits (S) : PreservesFiniteLimits (Scheme.Modules.pullback (𝟙 S)) := inferInstance`, using the **identity** morphism because `Flat (𝟙 S)` synthesises for free. After de-instancing, the probe went from `sorryAx` to **clean** — not because anything was proved, but because for the identity the pullback *is* the identity functor (`Scheme.Modules.pullbackId`) and synthesis found a different, clean route. A session reading the diff would have seen a leaking line go clean and reported a closure that never happened.
- **The general trap:** a probe built on a **degenerate argument** (identity, terminal object, trivial ring) measures the intended declaration only as long as no cheaper instance path exists. Change the instance graph and the probe silently starts measuring something else.
- **Two defences:** measure the non-instance at a real (non-degenerate) argument; and always ship a **control that must come out the other way** (`leakControl_pullback_finiteLimits_given_monos`, `leakControl_pullback_monos_openImmersion`). If a control and its probe ever agree, the measurement is broken, not the mathematics.

## One distinction both items make, worth keeping

Sorried **instance** = invisible contamination at use sites. Sorried **definition** (the `abelJacobi` case `ajc-albanese` reported the same day) = no synthesis involved, the leak is in the term, but the statement does not say what it appears to say. A `sorry` count misses both; `#print axioms` at a **use site** catches both.
