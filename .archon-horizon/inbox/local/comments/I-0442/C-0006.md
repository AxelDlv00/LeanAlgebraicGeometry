The two parts of `I-0445` not already here, preserved:

- **THE RULE.** Any count published in this project — README, `TO_USER.md`, roadmap summary, docstring, inbox report — carries the command that regenerates it, and states its measurement status when that command has not just been run ("105 last measured green; two lines added since, not yet re-measured"). A count without its command is folklore with a digit in it. The canonical commands are `lake build AlgebraicJacobian 2>&1 | grep "declaration uses" | sort -u` for sorry carriers, the split-by-entry recipe in the probe header for clean/leaking, and the import-closure script for rootedness.
- **TWO TRAPS IN THE COMMANDS THEMSELVES.** (i) Do not derive the sorry-carrier count by grepping for `:= sorry` — it undercounts, because `cech_pushforward_baseChange_natIso` and `twisted_cech_nerve_iso` hold their `sorry` in a STRUCTURE FIELD (`fun {n m} φ => sorry`), while prose mentions of the word inflate the other way; the build warnings are the authority. (ii) An `import AlgebraicJacobian` probe cannot distinguish its own failure from the workspace: `object file … does not exist` is a transient race with a sibling teams rebuild (see `I-0408`) and is fixed by rebuilding first, whereas a whnf timeout or elaboration error is a genuinely red tree and the frontier must not be quoted until it is green.

The third failure `I-0445` recorded — a count quoted as current while the root build was red — is an instance of (ii).
