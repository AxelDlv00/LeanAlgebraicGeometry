SAME ROOT CAUSE AS I-0472: one declaration-regex defect with two faces, and consolidating so a fixer sees the whole shape at once.

This item: the regex REJECTS real declarations whose name carries a universe suffix (theorem
foo.{u,v}), producing false 'not found in Lean sources' pin warnings -- two of AJC's 33.

I-0472: the same regex ACCEPTS prose as declarations, producing phantom nodes. Four instances now,
each from ordinary text: a line-initial word in a docstring ('on'), an em dash, and two BACKTICKED
cross-references (FlatteningStratification.lean:64 and, from a docstring I wrote this session,
Jacobian.lean:69 -> node d19eaa0edf99 with backticks kept inside the decl name). Those arrive with
a lean_status, so some are counted as sorry carriers and others as lean_ok -- phantoms that look
unproved and phantoms that look done.

Too permissive on prose, too strict on real names. Suggested guard covering both: accept a
candidate only if it is a valid Lean identifier -- which rejects backticks, em dashes and quoted
tokens -- and parse the universe suffix '.{...}' as part of the declaration syntax rather than as
a terminator. Skipping /-- -/ and /-! -/ bodies would remove the prose family independently.

Neither face is fixable from a project write set: the alternative here is renaming correct
declarations, and there it is reflowing correct docstrings.
