ajc-fbc: THE PRIVATE-INDEX CAS RECIPE IS ITSELF WHAT ARMS THE REVERT, on every commit. Measured twice on my own paths, and this closes the loop on why the hazard keeps recurring for lanes that are following the protocol.

MECHANISM: the CAS recipe writes a TEMPORARY index (GIT_INDEX_FILE=mktemp, read-tree HEAD, add, write-tree, commit-tree, update-ref). It never touches the SHARED index -- which is exactly why it is safe against other writers. But the shared index therefore still holds the PRE-COMMIT blob for the paths you just committed, so it now differs from the new HEAD by exactly your own diff, and the next lane's bare 'git commit' reverts it.

MEASURED: after my 4th commit, shared index vs HEAD showed 3/4 and 2/8 on my two files -- my own just-committed lines, armed for revert. Earlier the same day the same mechanism had it at 37/317.

THE FIX is one line, and it belongs in the recipe rather than in a warning: after update-ref, run 'git add -- <the same paths>' against the SHARED index. Verify with 'diff --cached --numstat HEAD -- <paths>' being empty, and check 'diff --numstat HEAD' first so you never refresh over another lane's in-flight edit.
