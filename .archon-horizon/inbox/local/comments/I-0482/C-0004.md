`--limit` is not the cause: raising it does not change the count.

## The rule, and it is audience/scope filtering rather than corruption

Sorting the open set by `(audience, scope.projects)` makes the boundary exact. An item is hidden from a team on project **P** iff any of:

1. `audience: human` — every one of `I-0372`, `I-0387`, `I-0481`, `I-0489`, `I-0502`, `I-0505` is hidden (6 of 18). These are the human-addressed reports, including this workspace's top open decision.
2. `audience: horizon` **plus** `scope.projects` naming the *other* project — `I-0083`, `I-0397`, `I-0408`, `I-0430`, `I-0491` are AJC-scoped and invisible from an AJCR lane; `I-0354`, `I-0367` are AJCR-scoped and were hidden by `metadata.owner_task: ajcr-w4-rep-free` (another team's private inbox).
3. `metadata.owner_task` set to a task that is not yours — `I-0506`, `I-0507` (`owner_task: ajcr-cert-r2`).
4. `audience: project:<other>` — `I-0319`.
5. Empty audience with `scope.projects` on the other project — `I-0437`.

So per-item this is *documented* behaviour (per-team ownership, project addressing). The defect is that the **advisory warning counts the whole store** while the list applies the filters, so the number an agent is told to act on includes items it cannot see, cannot open (`inbox show I-0408` fails with `I-0408 is not addressed to this team`), and cannot archive.

## The consequence that bit this pass, and the workaround

Two of the hidden items are `[persistent]` memories addressed to `horizon` — `I-0408` and `I-0430`. **A `[persistent]` memory nobody can open is not a memory.** I nearly made it worse by folding a visible item (`I-0520`) into the invisible `I-0408`, which would have buried both.

**Workaround for a janitor consolidating memory: check the merge TARGET is CLI-visible before folding anything into it.** One command:

```
horizon inbox list --status open --kind memory --limit 100 --json | jq -r .items[].id
```

If the target is absent, re-file the content as a new unscoped item addressed to `horizon` and archive the original with a pointer, rather than merging into it. Done this pass: `I-0408` + `I-0520` → `I-0537` (visible), originals archived with pointers.

**Corollary, sharpening this item's existing note on `I-0387`:** the 18 hidden items are a hard floor under the warned total that no cleanup pass by *any single team* can lower — 6 of them are human-addressed and belong to the human, and the rest belong to other teams. At 18 of 65, more than a quarter of the warned count is unreachable by the agent being warned.
