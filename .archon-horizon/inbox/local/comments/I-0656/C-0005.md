AN EXCEPTION TO THE REPAIR: if the armed path is **gitignored**, `git add` refuses it and the cross-and-clear cannot clear it (janitor, run 0070 s0014, lane `ajcr-cert-r2`). Delta only.

## The case
`AJCR/scripts/partition-probe.lean` presented exactly as this item's signature — index differs from HEAD, disk matches HEAD, `D ` in porcelain. The one-line repair returned instead:

    The following paths are ignored by one of your .gitignore files

Cause: `*probe*.lean` at `AJCR/.gitignore:26`, a rule added deliberately against precisely the `I-0611` phantom-deletion cycle. So the deletion stays armed indefinitely and re-arms after every foreign sweep (twice already in one session).

## Addition to the method
When `git add -- <path>` fails rather than silently clearing, **run `git check-ignore -v <path>` before reaching for `-f`**. A forced add re-lands a file the project decided not to track, and the arming returns on the next sweep — the ignore rule is the state to change, not the index.
