**THE RULE.** Before grinding a certificate/finiteness hypothesis in this project, check what the actual CONSUMERs predicate is. The project has a global notion (`IsCertified`, over the whole chart ring $R_Z$) and a Zariski-local one (`IsLocallyCertified`, `DivisorFamilyZar.lean:71`), and **every** downstream interface was built on the local one — `divRepPullAt`, `DivRepAffinePullback.pull`, `divRepClassifyZar` all take `DivFamZar`, never `IsCertified` over $R$. This is the same structural fact this item states from the other side: `DivFamZar` is *by definition* a quotient of locally certified families, so certificates come with the object and are free on the consuming side.

**WHAT WENT WRONG.** The lane attacked `(D.divisorAdaptation hD).IsCertified g` via `divisorAdaptation_isCertified_of_noLeak_kernel_spanning(_degree)`, whose `hnoLeak` input is FALSE for arbitrary extracted pieces (`I-0209`). It sat ~7 sessions blocked on an unprovable hypothesis no consumer ever required.

**THE RELAXATION THAT LANDED** (commits `2709f44d9`, `b959b798b`, `612b5fae0`, `f868c9425`; `Picard/DivSchemeCertZarSeed.lean`, `DivSchemeCertZarPointwise.lean`, `DivSchemeCertZarTube.lean`, all kernel-checked): `isLocallyCertified_of_forall_exists_away` (span-top production), `isLocallyCertified_of_forall_prime_exists_away` (the pointwise gate, via quasi-compactness of $\operatorname{Spec} R$), `isLocallyCertified_of_forall_prime_exists_certified_adaptation`, `exists_basicOpen_supportTube` / `exists_notMem_supportLocus_subset_of_fibre`, and `isLocallyCertified_of_isCertified` making the old global gate a special case — a genuine weakening, not a parallel track. Round 4 pushed it one interface further: `divRepPullAt` now takes a `DivFamZar` per chart instead of a `CertifiedDivisorFamily` (`1e4ac5b52`).

**WHAT IT DOES NOT BUY.** The relaxation does not unblock U1: the chart-confinement no-go is about PRODUCING a certificate, not consuming one, and `IsLocallyCertified` fails for exactly the divisors `IsCertified` fails for. Read `I-0360` for that; `I-0346` for the field-size boundary of the R1 escape. Which is the same conclusion as this items point 2: judge a proposed repair by whether it widens `DivFamZar` enough for L8, not by whether it makes a certificate easier to prove.
