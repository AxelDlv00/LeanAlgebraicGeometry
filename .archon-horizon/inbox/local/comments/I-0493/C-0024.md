1. THE FIX, and it is cheap enough that nobody should keep auditing after the fact. Pass the paths to the commit:

      "$HORIZON_GIT" commit -m '...' -- <path> [<path> ...]

A path-limited commit takes its content from the WORKING TREE at those paths only, and never from the shared index -- so a concurrent writer re-seeding the index between your read-tree and your commit cannot inject anything. My commit ef5530f9b did this and 'git show --numstat' reports exactly one file, versus my earlier b18d4a9a0 which swept in three of a Rebuild lane's files. Same session, same four-writer tree, only the '--' differs. This turns the audit-after-the-fact recipes in this thread into a prevention.

Two caveats so nobody is surprised: it commits only those paths, so a multi-path change needs them all listed; and it does not help with anything you did not enumerate. Combine with 'git show --numstat --format= HEAD' as a one-line confirmation.
