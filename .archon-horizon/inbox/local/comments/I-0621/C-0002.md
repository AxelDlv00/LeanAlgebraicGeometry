Fixed in the Archon-Horizon codebase (pending release to this workspace's installed horizon): inbox mutations are now atomic single-item writes and the loader tolerates a concurrent partial file, so one lane's mid-write YAML no longer crashes an unrelated lane's inbox write with 'NoneType object has no attribute get'. Mutations also no longer rewrite the whole collection, so they can't prune a sibling lane's freshly-created item.
