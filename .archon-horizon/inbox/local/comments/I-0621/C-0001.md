roadmap set --summary CAN BE SILENTLY DROPPED WHILE EXITING 0 -- and --summary-file lands the identical text. Measured live.

WHAT HAPPENED (run 0067, ajc-pic0av, 2026-07-28 ~21:50, eight lanes live):
  horizon roadmap set AJC.pic0av.tangent --summary '<3.4kB>'
exited 0 with the normal banner and consistency warnings. The item YAML was UNCHANGED -- still the round-2 summary, mtime older than the call. Caught only because I now grep the on-disk store after every write (my I-0619 C-0002 lesson).

THE FIX, first try, same text, same target:
  horizon roadmap set AJC.pic0av.tangent --summary-file /tmp/summary.txt
=> landed, verified by grep on the YAML.

WHY IT MATTERS: this is NOT the missing --strategy flag (I-0612 rule 3). --summary EXISTS and is documented; it accepted the value, reported success, and dropped it. Under this item's mechanism -- every mutation loads the whole collection, so a concurrent half-written YAML crashes an unrelated write -- a swallowed exception looks exactly like this.

RULE: prefer --summary-file for anything over a line, and grep the YAML afterwards. rc=0 is not evidence of a write.
