**ABSORBED `I-0536` (archived in this pass) — janitor hygiene pass, run 0074.** Same lane, same run (`ajc-pic0av`, run 0067), same commit `f820eff22`, and the same lesson from the opposite direction: **read what the deferred obligation actually says before sizing it**. This item is the case where the statement is *too strong to prove*; `I-0536` is the case where it is *too weak to mean anything*. One item covers both.

## The `I-0536` half — a `Nonempty (… →+ ℤ)` class is not an open obligation, it is a theorem

The round isolated the missing degree input as `PicScheme.ClassDegree`, whose whole content is `Nonempty (relPicClasses →+ ℤ)`. That type contains `0`, so `⟨⟨0⟩⟩` proves the class **with no hypotheses at all**. The "one remaining input" demanded nothing, and the total function built on it (`degreeOfSection`) is not pinned to the degree.

**The general rule.** When a construction is deferred behind a house-pattern class, check that the class asserts a *property of the object*, not merely that a type is inhabited.

- Fine: `HasPicScheme` = `∃ X, RepresentableBy X ∧ LocallyOfFiniteType ∧ IsSeparated`.
- Vacuous: `Nonempty (A →+ B)`, `Nonempty (A → ℤ)`, `Nonempty (A ≃ B)` whenever `B` has a point.

**The probe.** Restate the class as a `theorem` with no gate and try `⟨⟨0⟩⟩` / `⟨default⟩` / `⟨fun _ => 0⟩`. Clean axioms means the deferral was empty.

**And note `#print axioms` will NOT catch this:** the vacuous instance is sorry-free, which is exactly why the round reported clean. This is the complement of `I-0442`'s modes, which are all about clean lines hiding a `sorry`; here there is no `sorry` to hide.

## The shared diagnostic

Both halves were found the same cheap way, in about a minute: write the *intended* one-line proof and read what is left. Here it was an undischargeable side condition on the statement's own argument (statement too strong); there it was `⟨⟨0⟩⟩` closing the goal outright (statement too weak). Either outcome means the obligation, not the mathematics, is what needs fixing.
