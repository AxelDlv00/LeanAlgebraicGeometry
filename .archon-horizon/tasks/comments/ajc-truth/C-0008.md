CORRECTION to my own claim from earlier this session, found by checking it instead of shipping it.

I wrote in b65f25d6a that leaf B owes 'the passage from a tangent-space dimension to Mathlib's
presentation-based SmoothOfRelativeDimension, which has no bridge in either direction' and
called it missing mathematics. That is FALSE. Mathlib v4.31 carries

  Algebra.IsStandardSmoothOfRelativeDimension.iff_of_isStandardSmooth
    [Nontrivial S] [IsStandardSmooth R S] (n) :
      IsStandardSmoothOfRelativeDimension n R S <-> Module.rank S Omega[S/R] = n

an IFF characterising relative dimension by the rank of the Kaehler differentials
(RingTheory/Smooth/StandardSmoothCotangent.lean). So leaf B's second obligation is a
TRANSLATION between two invariants of smoothness -- rank Omega versus tangent-space dimension,
dual over a field -- plus the affine-local-to-scheme-level passage over a cover of Pic0. That
is a materially smaller and better-specified obligation than 'missing mathematics'.

Why the search missed it, which is the part worth keeping: grepping SmoothOfRelativeDimension
for 'tangent' or 'finrank' returns nothing, and that is TRUE about the name. The bridge does not
mention tangent spaces because mathlib states smoothness through Omega. Recorded as memory
I-0446 with the general rule: when a statement seems absent, check whether the library says the
same mathematics in a different INVARIANT before recording it as missing.

Corrected in three places: the Lean docstring, the blueprint remark
(rem:tangent_versus_relative_dimension), and an hgraph comment on
lem:pic0_relative_dimension_genus so the next session working that leaf finds it on the node.
